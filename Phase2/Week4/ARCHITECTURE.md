# ARCHITECTURE.md

# Test Automation Suite Agent

Multi-Agent AI System -- Local-First MVP (Future SaaS-Ready)

Primary Stack: - API Automation → Java + RestAssured + TestNG/JUnit\
- UI (future extensibility) → JavaScript + Playwright\
- LLM → OpenAI / Azure OpenAI\
- Embeddings → Local Open-Source Model\
- Deployment → Local CLI + VSCode Plugin\
- Scope → Single Project Per Installation

------------------------------------------------------------------------

# 1. High-Level System Overview

The Test Automation Suite Agent (TAS-Agent) is a Planner--Executor
multi-agent AI system that:

1.  Generates full API automation frameworks from scratch\
2.  Retrieves contextual service knowledge using RAG\
3.  Generates intelligent, risk-aware, contract-driven test cases\
4.  Performs self-correcting validation loops\
5.  Detects impact and auto-patches with developer approval

------------------------------------------------------------------------

# 2. Core Sub-Agents

1.  Skeleton Framework Generator Agent\
2.  Service Knowledge Retriever Agent (RAG-based)\
3.  Intelligent Test Case Generator Agent\
4.  Orchestrator (Planner--Executor Pattern)

------------------------------------------------------------------------

# 3. System Architecture (Local-First)

CLI / VSCode Trigger\
→ Planner (LLM-driven)\
→ Execution Plan (Task Graph JSON)\
→ Service Knowledge Retriever\
→ Skeleton Framework Generator\
→ Intelligent Test Case Generator\
→ Build Validator (Compile + Dry Run + Schema Validation)\
→ Self-Correction Loop (if required)\
→ Developer Approval (if patch)

------------------------------------------------------------------------

# 4. Input Knowledge Sources

Full Vector (V): - Requirements (User Stories / BRD)\
- UI Specs\
- Grooming Session Transcripts\
- Existing Test Assets\
- Technical Documentation (Swagger, Wiki)\
- Defect Database (UAT + Prod)\
- Release Notes

Partial Vector (PV): - PR Titles & Descriptions\
- Commit Messages\
- Changed File Paths\
- Method Signatures\
- Swagger Contract Diffs\
- Branch Metadata

(No source code logic indexed.)

------------------------------------------------------------------------

# 5. Orchestrator Agent Design

Planner Responsibilities: - Interpret trigger intent\
- Build structured execution plan\
- Select required agents\
- Handle retries and re-planning\
- Manage confidence scoring

Self-Correction Loop: If failure occurs (compile error, insufficient
context, swagger parse issue): 1. Planner analyzes structured failure\
2. Refines plan\
3. Re-executes failed step\
4. Stops after retry threshold

------------------------------------------------------------------------

# 6. Service Knowledge Retriever (RAG)

Architecture: Ingestion → Local Embeddings → Local Vector Store →
Retriever → Context Pack Builder

Retrieval Includes: - Story context\
- Swagger contract\
- Defect patterns\
- PR metadata\
- Release notes

Produces structured context pack for generation.

------------------------------------------------------------------------

# 9. Swagger Integration

-   Schema validation assertions\
-   Contract drift detection\
-   Auto-generation of schema validators\
-   Change impact detection on version change

------------------------------------------------------------------------

# 10. Change Impact & Auto-Patch

Produces structured ChangeImpactReport.

Auto-patches only within protected code regions:
`<AUTO-GENERATED-START>`{=html} `<AUTO-GENERATED-END>`{=html}

Requires developer approval before finalizing.

------------------------------------------------------------------------

# 11. Validation & Reliability

1.  Compile validation (mvn clean compile)\
2.  Dry-run execution (mvn test -DdryRun=true)\
3.  Schema integrity verification

Failures trigger planner self-correction.

------------------------------------------------------------------------

# 12. Memory Architecture

Local project memory stored in .tas-agent/: - Generation decisions\
- Naming conventions\
- Known flaky endpoints\
- Test hash signatures

Abstracted for future SaaS migration.

------------------------------------------------------------------------

# 13. Observability

Normal Mode: - Step-level logs\
- Execution summary

Debug Mode (--debug): - Plan JSON\
- RAG sources\
- Retry traces\
- Confidence scores\
- Token usage

------------------------------------------------------------------------

# 14. Security Model

MVP: - Secrets stored in environment properties\
- Never logged\
- Never embedded\
- Never sent to LLM

Future-ready via SecretProvider abstraction.

------------------------------------------------------------------------

# 15. Extensibility

Future agents may include: - Self-Healing Agent\
- Flaky Test Analyzer\
- Performance Test Generator\
- Security Test Agent

All agents follow structured execution contract.

------------------------------------------------------------------------

# Final Statement

This architecture defines a self-correcting, contract-aware,
defect-intelligent, enterprise-grade API test automation agent system
designed for immediate developer productivity and long-term SaaS
evolution.
